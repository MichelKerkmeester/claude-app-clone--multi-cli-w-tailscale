## OGAM-main (Off Grid AI)  —  relevance: **HIGH**

- **What it is:** A privacy-first mobile AI suite ("Off Grid AI") that runs LLM chat, tool-calling, vision, voice, and image generation entirely on-device, and can also connect to OpenAI-compatible remote servers (Ollama/LM Studio/LocalAI). At its core it is a streaming chat/transcript UI with tool calls, reasoning display, attachments, and a "draft-then-approve" action model.
- **Tech:** React Native 0.83 + React 19.2 (React Compiler enabled), TypeScript, Zustand (persist middleware over AsyncStorage) for state, React Navigation, native iOS (Swift)/Android (Kotlin) modules. Platform: native mobile + Mac Catalyst (not web/PWA). It IS a mobile AI chat app with tool-calling and remote-server streaming; it is NOT a remote-agent-control app, but the chat/streaming/tool half is a very close sibling.
- **Relevance:** High overlap on the exact surfaces Pi Remote cares about: a streaming chat transcript, an SSE/NDJSON streaming parser (parallels our WebSocket relay), a resilient tool-call loop with a draft/approve model (parallels our plan-mode + approvals), attachments, reasoning/thinking display, tool-call/result rendering (parallels our artifacts), and mobile ergonomics (composer, autoscroll, keyboard, haptics). Its remote-server layer (capability detection, health, discovery) mirrors our relay/agent-connection concerns. State architecture is Zustand factories with strong MVVM/SSOT doctrine — directly comparable to our *.svelte.ts logic factories. What does NOT transfer: on-device inference (llama.rn/executorch/litert), GPU/NPU/hardware, Stable Diffusion image gen, the model download manager, whisper/voice native modules, and native Swift/Kotlin code.

## mobilecli-main  —  relevance: **HIGH**

- **What it is:** MobileCLI's Rust daemon — the desktop server half of a phone app that remote-controls AI coding CLIs (Claude Code, Codex, Gemini, OpenCode) and plain shells. It allocates a PTY per session, streams terminal bytes over a LAN/Tailscale WebSocket to a paired phone, detects when the CLI is waiting for a tool approval / plan review / question and fires a push notification, and (Pro) exposes a security-jailed filesystem browse/edit/search/upload bridge. It is the exact product category as Pi Remote, minus the client UI.
- **Tech:** Rust daemon (tokio async, tungstenite WebSocket, serde JSON, portable-pty, hmac/sha2/subtle for auth); ~15k LOC across cli/src. The client is a React Native / Expo app (xterm.js, expo-secure-store, Expo push, RevenueCat) but that lives in a SEPARATE repo NOT present here — this checkout is server-side only. It IS a remote-agent / mobile-terminal app, so the domain matches Pi Remote; only the layer (daemon) and language (Rust) differ.
- **Relevance:** High-relevance sibling, same problem domain — remote-controlling an AI coding agent from a phone with approvals, plan-mode, reconnection, pairing, and notifications — but it is the SERVER half in Rust, not a SvelteKit client. So the value is in the CONTRACT and BEHAVIORS a client must mirror, not in UI/component/a11y code (there is none here; the RN client is elsewhere). The transferable gold is concentrated and unusually well-designed: an Attach-v2 reconnection/replay handoff (protocol.rs:318-355, daemon.rs:2369-2680), a wait-state taxonomy + dedup/clear state machine that is almost a 1:1 map of Pi's plan-mode+approvals (detection.rs, daemon.rs:1459-1520), a no-account scoped verifier challenge-response pairing model (auth.rs), a path-jail + rate-limit + structured-error filesystem contract (filesystem/security.rs, rate_limit.rs, protocol.rs FileSystemError), and a QR onboarding/connection-mode flow (setup.rs, qr.rs). Pi Remote consumes a relay; this shows what a good relay should emit and how a client should reattach, dedup, and stay secure.

## nodeterm-main  —  relevance: **HIGH**

- **What it is:** nodeterm is an Electron "node-based terminal + agent manager": real terminals and AI coding agents (Claude Code / Codex / Gemini / Grok / opencode / Copilot) live as draggable nodes on an infinite pan/zoom canvas, each in a persistent tmux session, with a kanban board of live sessions. Critically for us, the same core also runs headless as a Server Edition (browser client over WebSocket) and pairs with an iOS companion that attaches to the same live agent sessions over an end-to-end-encrypted relay — so it is the desktop/server/mobile trio of exactly the remote-agent-control problem Pi Remote solves.
- **Tech:** TypeScript monorepo. Electron shell (src/main + src/preload) + React 18 / zustand renderer (src/renderer, @xyflow/react canvas, xterm+tmux+node-pty terminals, Monaco). A headless Node "Server Edition" (src/server) reuses the SAME renderer over a WebSocket-RPC bridge. Heavy framework-free pure-TS core (src/core, src/shared) holds the agent/relay/status/approval logic. Security via tweetnacl (NaCl box) over a dumb relay. Separate iOS companion repo (not in checkout; contract lives in docs/ios-protocol-migration.md). It is NOT itself a mobile app, but it is a remote-agent orchestration app explicitly architected around a first-class mobile/browser remote client — the desktop half of a mobile-chat-over-relay system.
- **Relevance:** Extremely relevant — arguably the single closest sibling possible. Pi Remote is a mobile web PWA that remote-controls a coding agent over a WebSocket relay with plan-mode, approvals, transcript UI, and a strict security + a11y posture; nodeterm is the desktop/server/iOS implementation of that same system and has already solved, in production and with obsessive documentation, the exact subsystems Pi Remote needs: (1) a hardened E2EE relay + mutual-SAS pairing protocol with a byte-exact wire contract written FOR a mobile client (docs/ios-protocol-migration.md); (2) a "one core, many clients" transport seam (RpcClient over a pluggable FrameTransport) so the same app code runs over direct WS or the relay tunnel; (3) an agent-status state machine (working/waiting/blocked/done) driven by hooks with all the nasty edge cases handled; (4) multi-provider transcript normalization; (5) a deterministic hook-reply approvals mechanism (Allow/Deny IS the hook reply, not keystroke injection); (6) a full mobile Inbox/activity/usage contract; (7) reconnect/offline session lifecycle for flaky networks; (8) presence-aware push notifications. The ONLY off-target half is the desktop-native surface: the xterm/tmux terminal emulator, the @xyflow spatial canvas, kanban, Monaco/diff nodes, git/worktree/GitHub integration, whisper dictation, notch-HUD. Framework differs (React/zustand vs our Svelte 5 runes), but nodeterm deliberately keeps its logic in framework-free pure TS (src/shared, src/core), so the LOGIC and state SHAPES port cleanly; only the JSX components don't.
