# Research charter — ogam (target: specs/context/OGAM-main)

**Target (READ-ONLY):** specs/context/OGAM-main — A privacy-first mobile AI suite ("Off Grid AI") that runs LLM chat, tool-calling, vision, voice, and image generation entirely on-device, and can also connect to OpenAI-compatible remote servers (Ollama/LM Studio/LocalAI). At its core it is a streaming chat/transcript UI with tool calls, reasoning display, attachments, and a "draft-then-approve" action model.

**Goal:** mine adoptable patterns for the Pi Remote SvelteKit mobile chat / remote-agent PWA. Findings only (no code changes here, no writes to the target repo). Cite file:line.

**Non-goals:** on-device inference / native modules / anything platform-specific that does not transfer to a web PWA. Never modify specs/context/**.

**Stop conditions:** convergence (newInfoRatio < 0.05) or 10 iterations.

**Angles:**
- [logic] How does OGAM model a streaming assistant reply as a single-identity state machine from before-first-token through finalization, so a live stream, its persisted record, and (in their case) a paired device never duplicate, orphan, or leak state?
  - extract: The uuid-minted-at-startStreaming pattern; the NO_REPLY_FORMING single-source Pick<StreamingFields> type that makes 'add a streaming field' a compile error until it is cleared in one place; the ephemeral-end-BEFORE-durable-mutation ordering in finalizeStreamingMessage; resetStreamingSegment for multi-segment reasoning/answer; clearStreamingMessage vs finalize (orphan handling).
  - where: src/stores/chatStore.ts, src/stores/chatStoreReplyFinalization.ts, src/stores/chatMessageMutationActions.ts, src/stores/chatPersistence.ts
- [logic] What makes OGAM's tool-calling loop crash-proof and race-proof — how does it guarantee a failing/empty tool result is never mistaken for success, a user-stop never zombies a generation, and a malformed/rejected tool schema still yields an answer?
  - extract: The typed ToolResult (status ok|empty|error + errorCategory timeout|network|validation|not-found|internal); executeToolCallSafely as the single defensive seam that normalizes every throw/empty; the PER-TURN `interrupted` truth vs the service's shared abort flag (the race that painted 'No response' on a stopped turn); retry-without-tools on grammar/parse failures with streamed-error dedup (don't re-stream into the same consumer); the step-limit ceiling with a resumable user-facing notice.
  - where: src/services/generationToolLoop.ts, src/services/tools/types.ts, src/services/tools/toolResult.ts, src/services/tools/registry.ts
- [architecture] How does OGAM enforce the boundary that a reactive store is only a read-only UI projection while a service owns the authoritative state machine, side-effects, and resources — and how does its SSOT debugging doctrine prevent 'two sources kept in step by hand' bugs?
  - extract: The MVVM/MVP rule (Service owns state machine + side-effects; store is a thin projection; View dispatches intents); 'reactive stores are for UI projection NOT imperative coordination'; capability-as-data instead of Platform.OS/instanceof branching in callers; the three SSOT debugging questions and the symptom→two-sources→one-source table; how contextCompaction/generationSession services expose observable state without holding it in the store.
  - where: rules.md (sections: Architecture & Abstractions (SOLID), Platform Abstraction, Debugging — start with the source of truth), src/services/contextCompaction.ts, src/services/generationSession.ts, src/services/generationService.ts
- [ux] How does OGAM keep a streaming chat transcript fast and non-janky, and how does it render reasoning/thinking and tool call+result rows as first-class, collapsible transcript surfaces?
  - extract: messageRendererPropsEqual memo so only the 'streaming' item re-renders while historical messages keep stable refs; stableKey (toolCallId) surviving the streaming→finalized remount; the accordionStore keeping expanded state across remount; ToolResultBubble memo to stop press-target reset during streaming (tap-drop bug); per-call rows vs grouped rows for consistent rhythm; ThinkingBlock / pre-tool-call reasoning preservation; the ThinkTagParser that handles reasoning tags split across streaming chunks and multiple provider formats.
  - where: src/screens/ChatScreen/MessageRenderer.tsx, src/components/ChatMessage/index.tsx, src/components/ChatMessage/components/ToolMessages.tsx, src/components/ChatMessage/components/ThinkingBlock.tsx, src/services/providers/openAICompatibleStream.ts (ThinkTagParser)
- [ux] What are OGAM's mobile chat ergonomics for the composer, transcript autoscroll, keyboard, attachments, and failure messaging — the touch-first details that make a phone chat feel native?
  - extract: isNearBottomRef-gated scrollToEnd + jump-to-bottom FAB + maintainVisibleContentPosition + hide-list-until-initial-layout (no scroll jump); keyboard-aware popover anchoring (useKeyboardAwarePopover/useKeyboardHeight); the collapsing composer icon row + canSend/stop/voice action-button state machine; attachment preview + platform attach sheet; the haptic vocabulary (triggerHaptic types) mapped to actions; the buildNoVisionAlert pattern of failure messages that name the exact actionable next step.
  - where: src/components/ChatInput/index.tsx, src/components/ChatInput/Attachments.tsx, src/components/ChatInput/useKeyboardAwarePopover.ts, src/screens/ChatScreen/ChatMessageArea.tsx, src/hooks/useKeyboardHeight.ts, src/utils/haptics.ts
- [ease-of-use] How is OGAM's theme + design-token system structured so components never hardcode color/spacing/typography, support light/dark, and stay visually consistent under a documented brutalist/terminal design language?
  - extract: useTheme()/useThemedStyles(createStyles) factory that injects colors+shadows so styles are theme-reactive with zero hardcoding; the three-tier surface system + token tables (TYPOGRAPHY/SPACING/color roles); the component checklist (touch targets >=44px, contrast, uppercase labels, states); progressive-disclosure and information-density rules; how theme-independent tokens (constants) are split from theme-dependent (hook) values.
  - where: src/theme/, src/constants/index.ts, docs/design/DESIGN_PHILOSOPHY_SYSTEM.md, docs/design/VISUAL_HIERARCHY_STANDARD.md
- [other] How does OGAM keep long chat sessions within a bounded context budget and harden its LLM I/O against prompt injection and untyped failures — the long-session-resilience and safety posture?
  - extract: The context-window budget ratios (system/summary/recent/generation/overhead) and the summarize-older-then-keep-summary+recent flow with a persisted compactionSummary/cutoff; compaction state exposed as a service-owned observable (subscribeCompacting) rather than store state; the summarizer system prompt that explicitly instructs the model to NOT follow instructions embedded in the transcript; the coarse error taxonomy (ToolErrorCategory, isNonRetryableError, isToolGrammarError) used to decide retry-vs-fail.
  - where: src/services/contextCompaction.ts, src/stores/chatStore.ts (updateCompactionState/compaction fields), src/services/generationToolLoop.ts (error classification), src/services/tools/types.ts
