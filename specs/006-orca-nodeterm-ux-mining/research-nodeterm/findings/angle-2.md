# nodeterm UX mining — Angle 2: Live presence & status derivation

> How nodeterm decides a session's live state (running / needs-you / idle / stale / interrupted / unknown) and reconciles it live, mapped onto our host-authoritative, fail-closed mobile client.

## Orientation (what's where, and the key mapping)

`src/core/presence/` is **team presence** (multiplayer cursors/chat/focus over a WebSocket hub) — NOT agent-session status, and process-owning, so it is out of scope for Angle 2. The real presence/status derivation lives in three portable, mostly-pure layers:

- `src/shared/agents/normalize.ts` — per-agent hooks → one `AgentState = working | waiting | blocked | done` (+ `idle` / `interrupted` / `newTurn` / `awaitingInput` flags).
- `src/shared/agents/stale.ts` + `src/core/agent-status-mirror.ts` — the single stale-decay decider and the host-authored, phone-shaped read-only mirror.
- `src/renderer/lib/sessionList.ts` + `src/renderer/state/agentStatus.ts` + `src/renderer/canvas/Canvas.tsx` — the home/sidebar bucketing, the device-local unread bit, and the "never mark a watched session unread" edge.

**The load-bearing DTO mapping.** Our `SessionCardDto.status = 'idle' | 'running' | 'interrupted' | 'unknown'` (`packages/pi-rpc-protocol/src/types.ts:430`). nodeterm's model maps onto it as: `working→running`, `done→idle`, `interrupted→interrupted`, `undefined→unknown` — but nodeterm's **`waiting` / `blocked` ("needs-you") has NO value in our enum**. That single gap frames half the findings below.

Constraint legend: **(a)** view over existing DTO (`status` / `messageCount` / `updatedAt` / `epoch`); **(b)** pure interaction / device-local view-state; **(c)** needs a new host-published read-only field/RPC.

## Summary of the DTO deltas Angle 2 implies

- **Ships today over existing fields (✅):** ND-2.3 (status bucketing), ND-2.4 (watching-gated unread), ND-2.5 (read⟂workflow policy), ND-2.6 (done-holdoff), ND-2.7 (asymmetric rescue), ND-2.1 client-side decay, ND-2.8 never-fabricate.
- **Host-field asks (⚠️), in priority order:** a **needs-you / attention signal** with approval-vs-question sub-kind (ND-2.2 — the single biggest gap, reinforcing the existing `007-host-requests` `attention` enum); a host-side **stale decider / end-reason** so a presumed-gone session isn't mistaken for a finish (ND-2.1 / ND-2.9); a cross-surface **read-ack RPC** (ND-2.10); optionally a second **`stateEnteredAt`** clock (ND-2.8).
- **Not portable (❌):** none in-scope — nodeterm's *derivation logic* is portable; only its process-owning presence hub (multiplayer cursors) and PTY ownership are ❌, and those aren't Angle-2 material.
