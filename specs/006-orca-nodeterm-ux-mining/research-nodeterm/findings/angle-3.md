# Angle 3 — Session-card content model

**Focus:** what nodeterm renders *per session* on its board card / session row — human title, task/activity line, last-activity preview, agent/model identity, a context-window meter, timestamps, badges — mapped onto OUR home card, which today draws only `SessionCardDto { id, status: 'idle'|'running'|'interrupted'|'unknown', updatedAt, messageCount }` (confirmed `packages/pi-rpc-protocol/src/types.ts:428`) and shows `compactId(id)` as the label plus `"N blocks · <relative>"` (confirmed `app-mobile/src/pages/home/screen-home.svelte:101-103`, under the rule "Opaque identifiers only. No prompts, paths, or host context.").

**Constraint key:** (a) view over existing DTO fields · (b) pure interaction/layout · (c) needs a new host read-only field/RPC. Verdict: ✅ drop-in · ⚠️ needs host field · ❌ not portable.

**Paths** are relative to `specs/context/nodeterm-main/`. Read-only mining; nothing under `specs/context/` was modified.

**Framing.** nodeterm's card is a *projection*, never client-authored — the same discipline our fail-closed home needs. Its clearest "what a host publishes to a phone" model is `src/core/agent-status-mirror.ts`, the read-only JSON side-channel nodeterm writes for its OWN mobile companion (`MirrorFile.nodes[id] = {state, agentId, sessionId, name, updatedAt}` plus a per-node `InboxNodeNow {activity, tool, contextPercent, prompt}`). That mirror is the direct analog of our relay DTO, so its extra fields are the sharpest read on what nodeterm's card model ADDS over orca's `007-host-requests` set (`title`, `lastMessagePreview`, `agent`+optional `model`, `attention`). The live-badge / status-glyph / stale-decay logic is Angle 2/Angle 1 territory (see ND-1.7, ND-2.x) — cross-referenced here, not re-claimed.

## Summary

- **10 findings.** Verdict split: **✅ 3 · ⚠️ 6 (one mixed with ✅) · ❌ 1.**
- **Standout wins:** (1) **ND-3.1 — a per-card context-window meter (model + fill %)**, the single best content-model idea nodeterm has that orca never proposed; it tells the user *which session is running out of context* over a tiny optional host number, fail-closed to nothing. (2) **ND-3.2 — a live host-derived "activity" line** ("Running npm test") that upgrades our bare "Working…". (3) **ND-3.8 / ND-3.7 — two free ✅ wins:** drop the peek-accordion for an always-inline detail row (supersedes orca 2.5), and a device-local "changed since you looked" dot over `updatedAt` that needs no host field; plus ND-3.9's deterministic color mark from the opaque id.
- **NEW host fields nodeterm's card model adds (NOT in orca-007):** `contextPercent` (ND-3.1, HIGH), `activity`+`tool` (ND-3.2, MED-HIGH), `prompt` (the "You:" turn-opening line, ND-3.3, MED). One niche/declined: a recurring-job (`loop`) signal (ND-3.10, ❌/⚠️-niche).
- **Already-in-orca-007 (reinforced, NOT re-requested):** `title` (ND-3.4 — confirms it must be a host projection of the session's own name, never client-sliced), `agent`+optional `model` (ND-3.5 — note the model rides the same usage payload as `contextPercent`, so bundle them), and `attention` (ND-3.6's NEEDS-YOU leg — our `status` enum has no waiting/blocked, so it stays host-dependent).
