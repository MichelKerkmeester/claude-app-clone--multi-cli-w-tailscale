# Angle 4 — Chat / message-level interactions (nodeterm)

Terminal/agent output rendering + message interactions in nodeterm, mapped onto OUR host-authoritative,
fail-closed, virtualized SvelteKit mobile transcript (`app-mobile/src/pages/chat/transcript/`).

**Rendering substrate differs.** nodeterm renders live PTY/xterm output; we render a host-supplied redacted
transcript snapshot. So every finding extracts the UX PATTERN, never the xterm/tmux plumbing.

**Constraint tags** — (a) client-side view over existing rendered data · (b) pure interaction/layout ·
(c) needs a new host field/RPC. **Verdicts** — ✅ drop-in · ⚠️ needs host support · ❌ not portable.

**What we already have (verified in our source):** per-code-block copy with a transient "Copied" confirm +
a11y announce + copy-failure message (`rich-content/card-code.svelte` + `use-copy-feedback.svelte.ts`);
per-answer Copy/Share (`transcript/assistant-actions.svelte`); find-in-artifact-viewer with `<mark>`
highlight (`artifacts/preview-controls.svelte` + `artifact-viewer-host.svelte`, per-preview `findTerm`);
virtualized transcript with live-edge follow + jump-to-latest pill + count badge
(`transcript/transcript-list.svelte`); a safe markdown/rich-content pipeline that allow-lists and rejects
unsafe input (`rich-content/`). We do **not** have: transcript-wide search, any link handling in assistant
prose, or a size-quantified copy receipt.

## Cross-cutting notes

- **Clipboard is write-only, size-capped, and rejects malformed input** (`terminal/osc52.ts:parseOsc52`,
  `MAX_BASE64 = 1_000_000`; a `?` read query is refused). We already use `navigator.clipboard.writeText`
  (write-only), so this is a guardrail, not a feature: never let rendered transcript content trigger a
  clipboard *read*, and cap any bulk-copy payload. Low relevance to a host-authoritative surface (no remote
  program reads our clipboard) — recorded, not promoted to a finding.
- **The find-index-decoupled-from-DOM pattern (ND-4.1) is the load-bearing architectural note** for any
  message-level navigation over our virtualized list: per-turn scroll (orca 3.1), search (ND-4.1), and
  jump-to-latest all need a flat model of the transcript that outlives what is currently mounted.
- **Everything here is (a) or (b).** No finding needs a host mutation or client-owned session truth. The one
  ⚠️ is file-path links (ND-4.4), which is deliberately punted to the existing artifact-viewer host route —
  consistent with orca 6.6 and our fail-closed rule.
