# Angle 1 — Parallel-session surfacing / the session board

**Focus (HEADLINE):** nodeterm's board of live Claude-Code sessions — lanes/grouping/ordering, live-status glyphs, board-vs-list, counts, empty/loading, selection/open — mapped onto OUR thin host-authoritative home list over `{id, status, messageCount, updatedAt, epoch}`.

**Constraint key:** (a) view over existing DTO fields · (b) pure interaction/layout · (c) needs a new host read-only field/RPC. Verdict: ✅ drop-in · ⚠️ needs host field · ❌ not portable.

**Paths** are relative to `specs/context/nodeterm-main/`. Read-only mining; nothing under `specs/context/` was modified.

**Headline correction to the seed:** the seed (`_seed-angle1-iteration001.md`, F-1..F-9) located "the board" as `components/kanban/` + `lib/kanban.ts` — the drag-assignment Trello board. That board is a *manual-assignment* layer (user-editable columns, `assignments[]`, card DnD) and is mostly ⚠️/❌ for us (it needs the client to own and mutate assignment truth). The **portable board logic is a different surface the seed never opened**: the sessions sidebar's **status-grouping mode** (`lib/sessionList.ts` `buildStatusList`), a *derived* flat list bucketed by live agent status. That is the direct ✅ analog to our home. Findings below extend/verify the seed rather than repeat it.

## Summary

- **12 findings.** Verdict split: **✅ 10 · ⚠️ 1 · ❌ 1.**
- **Standout wins (all ✅, all HIGH):** (1) ND-1.1 — the real portable board is nodeterm's *derived* status-grouped session list (`buildStatusList`), which the seed missed by fixating on the drag-kanban; it needs no host changes. (2) ND-1.2/1.3/1.4 — fixed attention-first always-present sections, first-match precedence (a running-but-unread session stays Running), newest-transition-first sorting that never fabricates a timestamp. (3) ND-1.6 — the 20-min stale→**unknown** decay, which refines orca 1.8's 30-min→idle to something more honest, purely presentational over `updatedAt`.
- **Host-dependent items:** only the *unread / needs-you* axis (ND-1.2, ND-1.3, ND-1.7's unread dot) needs a new host field — and it is **already covered by orca's `007-host-requests` `attention` enum on `SessionCardDto`; NOT re-requested.** ND-1.5 (a transition clock distinct from `updatedAt`) and ND-1.7's SLEEPING (`hibernated`) are flagged ⚠️/❌ but explicitly **recommended NOT to request** (our `updatedAt` suffices; hibernation is desktop-RAM-specific). No net-new host request beyond the orca set.
